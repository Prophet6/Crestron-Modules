File Reader v3.2.0

One user module and one shared library that store and restore digital, analog, and serial signals in a file on the processor.

Start here

File Reader v3.2.0 writes the signals on the symbol into a file, and reads that file back onto the outputs. Reads detect the format. Writes use the format you select. A successful write also copies the inputs onto the outputs.

User module

File Reader v3.2.0 is the symbol you drop in SIMPL Windows. F1 on that symbol opens this page.

SIMPL+ symbol

The paired SIMPL+ module is hidden. Its F1 help is the comment inside the .usp. Copy-after-write and auto-create live there.

Library

Library FileReader20260623, source FileReader20260623.cs, class FileDataHandler. Text detection, JSON, checksums, and encryption live in that library. A Visual Studio build names the .clz after that source file.

  1. Keep FileReader20260623.clz next to the SIMPL+ module. v3.2.0 links that archive. v3.1.1 and v3.1.2 linked the library name File Reader.
  2. Add File Reader v3.2.0. Set File_Location (for example \\NVRAM\\ or \\CF0\\) and Filename with no extension. Set Format. The default is 4, JSON.
  3. Expand the digital, analog, and serial pairs you need. The symbol ships with 64 of each type, and the arrays can be raised to 256. Empty or zero slots are ignored.
  4. Drive the inputs, then pulse Write. On success the file is stored and every input is copied to the matching output. Digitals are driven as an explicit 0 or 1.
  5. Pulse Read to load a file. Detected_Format and Feedback report what was found. Outputs stay where they were if the read fails.
  6. For startup, hold Enable_Auto_Create high and wire Set_Default_Values to the logic that drives the default inputs. A missing file is created. An existing file is read. An existing file is not overwritten.
Press F1 on the File Reader v3.2.0 user module to open this page. Leave File Reader v3.2.0 Technical Manual.html next to the .umc. The hidden SIMPL+ symbol does not open this file.
Path. The file is File_Location plus Filename, or Filename_Override when that string is not empty, plus the extension for the active format. Do not put the extension in the name.

Formats

Format chooses the file written. Reads ignore it and detect the format from the file. Format_Override replaces the parameter when its value is 1 through 6.

CodeFormatExtension
1Text.txt
2CSV.csv
3XML.xml
4JSON.json (default)
5INI.ini
6Binary.bin

After a read, Detected_Format is 1 through 6, -1 when the format is undetected or the read errors, or -2 when a non-JSON integrity check fails. A write does not change Detected_Format.

JSON

JSON may come from this module or from another tool. The reader looks for digitals, analogs, and serials arrays, at the top level or nested under data or signalData. Names are case-insensitive. Arrays may be shorter than 64; missing slots stay 0 or empty. Digital elements may be 0 or 1, integers, or JSON booleans. An optional crc32 field is ignored for pass or fail.

{
  "digitals": [0, 1, 0, 1],
  "analogs": [8, 16, 32, 64],
  "serials": ["Room A", "Scene 1", "", ""]
}

Boolean digitals are accepted, for example [false, true, false, true]. A write from this module stores a full 64-element set and may include crc32 for other tools. Readers do not require it.

Text detection looks for a valid CRC32: line and indexed D, A, and S lines. A loose text search used to mistake words inside JSON, XML, or CSV for the Text format. That check is in the shared library.

Use v3.2.0 when digitals must come back at startup. v3.1.1 does not drive Digital_Output reliably after a read. v3.1.2 has that drive fix, and does not copy inputs to outputs after a write or offer Enable_Auto_Create.

Auto-create

Hold Enable_Auto_Create high to replace an external routine that wrote defaults when the file was missing and read the file when it already existed.

  1. Hold Enable_Auto_Create high.
  2. Wire Set_Default_Values to logic that drives Digital_Input_[1-64], Analog_Input_[1-64], and Serial_Input_[1-64] with the default configuration.
  3. On startup, or when the effective path changes, a missing file pulses Set_Default_Values, waits Default_Settle_Time, writes, then copies the inputs to the outputs.
  4. An existing file is read onto the outputs. Auto-create does not overwrite it.
  5. One automatic action runs for a path. Changing the path allows another.

File_Busy_FB stays high through that sequence, including the settle wait and the write or read.

Backup and encryption

With Enable_Backup high, a write stores [Filename].[extension].bak in the same folder. With Enable_Backup_History also high, the previous backup is archived as .bak.yyyyMMdd.gz instead of being overwritten.

  • Pulse Restore_Backup to put the .bak back. Feedback reports Backup restored (swap) when that succeeds.
  • Pulse Delete_Backup to remove the .bak. Backup_Exists_FB follows the result.
  • Pulse Delete to remove the main file. Feedback reports File deleted successfully when that succeeds.

Set Encrypt high and provide Encryption_Key before a write that should be encrypted. A successful encrypted write reports File written in CSV format with checksum (encrypted), with the format name in place of CSV. On read, the header sets File_Encrypted_FB. Provide the same key. A decrypted read reports Valid CSV detected and parsed (decrypted), again with the detected format name.

A write with Encrypt high and no key fails. A read of an encrypted file with no key fails. The key has to match the key that wrote the file.

Non-JSON formats can fail the checksum. Detected_Format becomes -2 and Feedback reports Integrity check failed for Binary, with the detected format name in place of Binary. JSON does not fail the read because crc32 is missing or different.

Examples

JSON configuration

Store a volume, or any other persistent settings, and load them again at startup.

  1. Set Format to 4. Set File_Location to \\NVRAM\\ and Filename to config. Format 4 appends .json.
  2. Connect Analog_Input_1 to the volume level and set it to 50%.
  3. Pulse Write. Feedback reports File written in JSON format with checksum. The outputs copy the inputs. File_Exists_FB goes high.
  4. Pulse Read. Detected_Format is 4, Analog_Output_1 is 50%, and Feedback reports Valid JSON detected and parsed.

Encrypted CSV log

Log scaled analog readings with a backup.

  1. Set Format to 2. Set File_Location to \\CF0\\ and Filename to tempLog. Format 2 appends .csv.
  2. Hold Encrypt and Enable_Backup high. Set Encryption_Key to a 16-character key, such as MySecretKey12345.
  3. Connect Analog_Input_[1-5] to the sensors. Set Analog_Input_1 to 25000 for a scaled 25 degree reading, and set the rest.
  4. Pulse Write. The encrypted CSV and the .bak are created. Feedback reports File written in CSV format with checksum (encrypted). File_Encrypted_FB and Backup_Exists_FB go high.
  5. Leave the same key in place and pulse Read. The outputs fill from the decrypted file and Feedback reports Valid CSV detected and parsed (decrypted).
  6. If the main file is unusable, pulse Restore_Backup. Feedback reports Backup restored (swap).

Binary file, then delete

Write a compact temporary file, check it, and remove it.

  1. Set Format to 6. Set File_Location to \\CF0\\ and Filename to tempGameData. Format 6 appends .bin.
  2. Connect Digital_Input_[1-10], set them, and pulse Write. The file includes a checksum.
  3. Pulse Read. A valid file fills the outputs and File_Size shows the size. A tampered file sets Detected_Format to -2 and Feedback reports Integrity check failed for Binary.
  4. Pulse Delete. File_Exists_FB goes low and Feedback reports File deleted successfully.

Read XML, write INI

Load an existing file by detection, then store it in another format.

  1. Set Format to 3, File_Location to \\NVRAM\\, and Filename to legacy. Format 3 opens legacy.xml.
  2. Pulse Read. The file content is detected as XML, so Detected_Format is 3 and the outputs load.
  3. Copy those outputs onto the inputs. Set Format to 5 and Filename to newConfig. Format 5 appends .ini.
  4. Pulse Write. The new INI file is created, and the outputs copy the inputs that were written.

Versions

Document revision v3.2.0, 16 July 2026. Current packaging targets 4-Series.

v3.2.0 — 16 July 2026 — RGW / AI

  • A successful write copies digital, analog, and serial inputs to the matching outputs. Digitals use an explicit 0 or 1.
  • Enable_Auto_Create, Set_Default_Values, and Default_Settle_Time. A missing file is written from the defaults. An existing file is read. An existing file is not overwritten. One automatic action runs per path until the path changes.

v3.1.2 — 16 July 2026 — RGW / AI

  • SIMPL+ only: Digital_Output asserts after a successful read. Values from the Simpl# arrays are applied with an explicit 0 or 1.
  • Shared library: JSON reads accept industry-standard objects. Optional crc32 is no longer a hard reject.
  • Source stays FileReader20260623.cs. Library name stays File Reader.

v3.1.1 — 1 May 2026 — RGW

  • Shared library: Text detection uses structured markers, so a serial value such as a device name no longer makes a JSON, XML, or CSV file look like Text.
  • SIMPL+: parameter formatting was removed so the symbol could sit inside a user-module wrapper.
  • Programs still on v3.1.1 pick up the library fixes, and still need v3.1.2 or later for reliable digital outputs after a read.

Earlier

  • v3.1 — 25 February 2026. Added File_Not_Exist_FB as its own feedback.
  • v3.0 — 4 August 2025. First release, including JSON.
  • 5–6 August 2025. File existence, delete, busy, size, integrity, CSV, INI, backup and restore, AES encryption, backup history, Format_Override, Filename_Override, Delete_Backup, and the split of location and name with the extension taken from the format. Format codes became 1-based, Text through Binary.
