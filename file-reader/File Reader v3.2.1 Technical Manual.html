File Reader v3.2.1

One user module and one shared library that store and restore digital, analog, and serial signals in a file on the processor.

Start here

File Reader v3.2.1 writes the signals on the symbol into a file, and reads that file back onto the outputs. Reads detect the format. Writes use the format you select. A successful write also copies the inputs onto the outputs. With Match_Partial high, the file name you enter can be part of a longer name already on the processor.

User module

File Reader v3.2.1 is the symbol you drop in SIMPL Windows. F1 on that symbol opens this page.

SIMPL+ symbol

The paired SIMPL+ module is hidden. Its F1 help is the comment inside the .usp. Copy-after-write and auto-create live there.

Library

Library FileReader20261013, source FileReader20261013.cs, class FileDataHandler. Text detection, JSON, checksums, encryption, and partial name matching live in that library. A Visual Studio build names the .clz after that source file. Assembly version 3.2.1.0.

  1. Keep FileReader20261013.clz next to the SIMPL+ module. v3.2.1 links that archive. v3.2.0 linked FileReader20260623. v3.1.1 and v3.1.2 linked the library name File Reader.
  2. Add File Reader v3.2.1. Set File Location (for example \\NVRAM\\ or \\CF0\\) and Filename with no extension. Set Format. The default is 4, JSON.
  3. Expand the digital, analog, and serial pairs you need. The symbol ships with 64 of each type, and the arrays can be raised to 256. Empty or zero slots are ignored.
  4. Drive the inputs, then pulse Write. On success the file is stored and every input is copied to the matching output. Digitals are driven as an explicit 0 or 1.
  5. Pulse Read to load a file. Detected_Format_FB and Operational_Feedback report what was found. Outputs stay where they were if the read fails.
  6. For startup, hold Auto_Create_File high and wire Set_Default_Values to the logic that drives the default inputs. A missing file is created. An existing file is read. An existing file is not overwritten.
Press F1 on the File Reader v3.2.1 user module to open this page. Leave File Reader v3.2.1 Technical Manual.html next to the .umc. The hidden SIMPL+ symbol does not open this file.
Path. The file is File Location plus Filename, or FileName_Override when that string is not empty, plus the extension for the active format. Do not put the extension in the name. File Location is still the folder string you already use, including its trailing separator. With Match_Partial high, that name is a fragment. config and JSON select Boardroom1S25_config.json in the same folder. The comparison ignores case. Several matches use the first name alphabetically. No match uses the fragment as the whole file name, so auto-create can write config.json. On the symbol, both name signals are in the File_Info group. FileName_Override is across from FileName_FB. Match_Partial is the next input, and that row has no output. Size_FB is the next serial in the group. Auto_Create_File is at the bottom of File_Info, across from Set_Default_Values.

Formats

The Format parameter chooses the file written. The Format analog replaces that parameter when its value is 1 through 6. Format_Text through Format_Binary set the analog to 1 through 6. Reads ignore the selection and detect the format. Detected_Format_FB is across from the Format analog. Format_Text_FB through Format_Binary_FB follow the detected code.

CodeFormatExtension
1Text.txt
2CSV.csv
3XML.xml
4JSON.json (default)
5INI.ini
6Binary.bin

After a read, Detected_Format_FB is 1 through 6, -1 when the format is undetected or the read errors, or -2 when a non-JSON integrity check fails. A write does not change Detected_Format_FB.

JSON

JSON may come from this module or from another tool. The reader looks for digitals, analogs, and serials arrays, at the top level or nested under data or signalData. Names are case-insensitive. Arrays may be shorter than 64; missing slots stay 0 or empty. Digital elements may be 0 or 1, integers, or JSON booleans. An optional crc32 field is ignored for pass or fail.

{
  "digitals": [0, 1, 0, 1],
  "analogs": [8, 16, 32, 64],
  "serials": ["Room A", "Scene 1", "", ""]
}

Boolean digitals are accepted, for example [false, true, false, true]. A write from this module stores a full 64-element set and may include crc32 for other tools. Readers do not require it.

Text detection looks for a valid CRC32: line and indexed D, A, and S lines. A loose text search used to mistake words inside JSON, XML, or CSV for the Text format. That check is in the shared library.

Auto-create

Hold Auto_Create_File high to replace an external routine that wrote defaults when the file was missing and read the file when it already existed.

  1. Hold Auto_Create_File high.
  2. Wire Set_Default_Values to logic that drives Digital_Input_[1-64], Analog_Input_[1-64], and Serial_Input_[1-64] with the default configuration.
  3. On startup, or when the effective path changes, a missing file pulses Set_Default_Values, waits Default Wait Time, writes, then copies the inputs to the outputs.
  4. An existing file is read onto the outputs. Auto-create does not overwrite it.
  5. One automatic action runs for a path. Changing the path allows another.

Busy_FB stays high through that sequence, including the settle wait and the write or read.

Backup and encryption

With Enable_Backup high, a write stores [Filename].[extension].bak in the same folder. With Enable_Backup_History also high, the previous backup is archived as .bak.yyyyMMdd.gz instead of being overwritten.

  • Pulse Restore_Backup to put the .bak back. Operational_Feedback reports Backup restored (swap) when that succeeds.
  • Pulse Delete_Backup to remove the .bak. Backup_Exists_FB follows the result.
  • Pulse Delete to remove the main file. Operational_Feedback reports File deleted successfully when that succeeds.

Set Encrypt high and provide Encryption_Key before a write that should be encrypted. A successful encrypted write reports File written in CSV format with checksum (encrypted), with the format name in place of CSV. On read, the header sets Encrypted_FB. Provide the same key. A decrypted read reports Valid CSV detected and parsed (decrypted), again with the detected format name.

A write with Encrypt high and no key fails. A read of an encrypted file with no key fails. The key has to match the key that wrote the file.

Non-JSON formats can fail the checksum. Detected_Format_FB becomes -2 and Operational_Feedback reports Integrity check failed for Binary, with the detected format name in place of Binary. JSON does not fail the read because crc32 is missing or different.

Examples

JSON configuration

Store a volume, or any other persistent settings, and load them again at startup.

  1. Set Format to 4. Set File Location to \\NVRAM\\ and Filename to config. Format 4 appends .json.
  2. Connect Analog_Input_1 to the volume level and set it to 50%.
  3. Pulse Write. Operational_Feedback reports File written in JSON format with checksum. The outputs copy the inputs. Exists_FB goes high.
  4. Pulse Read. Detected_Format_FB is 4, Analog_Output_1 is 50%, and Operational_Feedback reports Valid JSON detected and parsed.

Encrypted CSV log

Log scaled analog readings with a backup.

  1. Set Format to 2. Set File Location to \\CF0\\ and Filename to tempLog. Format 2 appends .csv.
  2. Hold Encrypt and Enable_Backup high. Set Encryption_Key to a 16-character key, such as MySecretKey12345.
  3. Connect Analog_Input_[1-5] to the sensors. Set Analog_Input_1 to 25000 for a scaled 25 degree reading, and set the rest.
  4. Pulse Write. The encrypted CSV and the .bak are created. Operational_Feedback reports File written in CSV format with checksum (encrypted). Encrypted_FB and Backup_Exists_FB go high.
  5. Leave the same key in place and pulse Read. The outputs fill from the decrypted file and Operational_Feedback reports Valid CSV detected and parsed (decrypted).
  6. If the main file is unusable, pulse Restore_Backup. Operational_Feedback reports Backup restored (swap).

Binary file, then delete

Write a compact temporary file, check it, and remove it.

  1. Set Format to 6. Set File Location to \\CF0\\ and Filename to tempGameData. Format 6 appends .bin.
  2. Connect Digital_Input_[1-10], set them, and pulse Write. The file includes a checksum.
  3. Pulse Read. A valid file fills the outputs and Size_FB shows the size. A tampered file sets Detected_Format_FB to -2 and Operational_Feedback reports Integrity check failed for Binary.
  4. Pulse Delete. Exists_FB goes low and Operational_Feedback reports File deleted successfully.

Read XML, write INI

Load an existing file by detection, then store it in another format.

  1. Set Format to 3, File Location to \\NVRAM\\, and Filename to legacy. Format 3 opens legacy.xml.
  2. Pulse Read. The file content is detected as XML, so Detected_Format_FB is 3 and the outputs load.
  3. Copy those outputs onto the inputs. Set Format to 5 and Filename to newConfig. Format 5 appends .ini.
  4. Pulse Write. The new INI file is created, and the outputs copy the inputs that were written.

v3.2.1 — 13 October 2026 — RGW / AI

  • Match_Partial selects a file whose name contains Filename or FileName_Override. Several matches use the first name alphabetically. No match keeps the exact name so auto-create can write it.
  • FileName_FB reports that file name with its extension.
  • Library FileReader20261013, assembly 3.2.1.0.

v3.2.0 — 16 July 2026 — RGW / AI

  • A successful write copies digital, analog, and serial inputs to the matching outputs. Digitals use an explicit 0 or 1.
  • Auto_Create_File, Set_Default_Values, and Default Wait Time. A missing file is written from the defaults. An existing file is read. An existing file is not overwritten. One automatic action runs per path until the path changes.

v3.1.2 — 16 July 2026 — RGW / AI

  • SIMPL+ only: Digital_Output asserts after a successful read. Values from the Simpl# arrays are applied with an explicit 0 or 1.
  • Shared library: JSON reads accept industry-standard objects. Optional crc32 is no longer a hard reject.
  • Source stays FileReader20260623.cs. Library name stays File Reader.

v3.1.1 — 1 May 2026 — RGW

  • Shared library: Text detection uses structured markers, so a serial value such as a device name no longer makes a JSON, XML, or CSV file look like Text.
  • SIMPL+: parameter formatting was removed so the symbol could sit inside a user-module wrapper.
  • Programs still on v3.1.1 pick up the library fixes, and still need v3.1.2 or later for reliable digital outputs after a read.

Earlier

  • v3.0 — 4 August 2025. First release, including JSON.
