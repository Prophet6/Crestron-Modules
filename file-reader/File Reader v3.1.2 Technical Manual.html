File Reader Module v3.1.2 Technical Manual

Document revision: v3.1.2 (16 July 2026). Describes SIMPL+ modules File Reader v3.1.1 and File Reader v3.1.2, and the shared SIMPL# library File Reader (source: FileReader20260623.cs).

Overview: The File Reader module (comprising the SIMPL+ module and its paired SIMPL# library) provides a thread-safe interface for reading and writing up to 256 digital, analog, and serial signals to and from files on a Crestron processor. Supports Text, CSV, XML, JSON, INI, and Binary formats. Enables persistent storage and retrieval of system states, configurations, or data in Crestron control systems. Current packaging targets 4-Series processors (3-Series compile target optional/removed depending on program).

Key features include auto-detection of formats during reads, error feedback, mutex protection for concurrent operations, file existence and busy feedbacks, delete functionality, file size reporting, integrity checks with checksums (format-dependent), backup and rollback capabilities, optional AES encryption, and industry-standard JSON read support (shared library, both module versions).

Library compatibility: One shared File Reader CLZ/DLL backend is used by both v3.1.1 and v3.1.2 SIMPL+ symbols. Library improvements (text detection, JSON) apply to both. The digital-output drive fix after Read is implemented only in the v3.1.2 SIMPL+ module.

Inputs, Outputs, Parameters

Parameters:

  • Format (Integer): Specifies the file format for write operations. Options: 1 (Text), 2 (CSV), 3 (XML), 4 (JSON), 5 (INI), 6 (Binary). Default: 4 (JSON). Used only for writes; reads auto-detect the format.
  • File_Location (String): The path to the file (e.g., "\\NVRAM\\"). Ensure the path is valid on the Crestron processor (e.g., NVRAM or CF0). Required for both read and write.
  • Filename (String): The name of the file (e.g., "datafile"). Required for both read and write.

Inputs:

  • Read (Digital): Pulse high to trigger a read operation from the file specified in Filename. Loads data into the output signals if successful.
  • Write (Digital): Pulse high to trigger a write operation to the file specified in Filename, using the format from the Format parameter. Saves data from the input signals.
  • Delete (Digital): Pulse high to delete the file specified in Filename. Updates File_Exists_FB and Feedback on completion.
  • Delete_Backup (Digital): Pulse high to delete the backup file (*.bak) if it exists. Updates Backup_Exists_FB and Feedback on completion.
  • Enable_Backup (Digital): When high, enables automatic backup (.bak) on writes.
  • Enable_Backup_History (Digital): When high, enables archiving of previous backups to dated .gz files during write operations with backup enabled. If low, overwrites the .bak without archiving.
  • Restore_Backup (Digital): Pulse high to restore from .bak to Filename, if .bak exists.
  • Encrypt (Digital): When high, enables AES encryption on writes (using Encryption_Key).
  • Format_Override (Analog): Overrides the Format parameter at runtime if value is 1-6; otherwise, uses the parameter.
  • Filename_Override (String): Overrides the Filename parameter at runtime if non-empty; otherwise, uses the parameter.
  • Digital_Input_[1-64] (Digital): Digital input values (0 or 1) to be written to the file. Ignored during read operations.
  • Analog_Input_[1-64] (Analog): Analog input values (0-65535) to be written to the file. Ignored during read operations.
  • Serial_Input_[1-64] (String): Serial input strings (up to 256 characters each) to be written to the file. Ignored during read operations.
  • Encryption_Key (String): The encryption key (e.g., a 16-character string for AES-128). Required if Encrypt is high.

Outputs:

  • Detected_Format (Analog): After a read operation, indicates the auto-detected file format: 1 (Text), 2 (CSV), 3 (XML), 4 (JSON), 5 (INI), 6 (Binary), or -1 (Error or undetected), -2 (Integrity check failed for non-JSON formats that use a hard CRC check). Remains unchanged after writes. JSON: optional crc32 is not required; industry-standard JSON objects are accepted without failing integrity solely for CRC mismatch.
  • Feedback (String): Provides status or error messages after read/write operations (e.g., "Valid JSON detected and parsed" or "Error: File not found"). Useful for debugging or display on touchpanels.
  • File_Exists_FB (Digital): High (1) if the file at Filename exists, low (0) otherwise. Updated on module initialization and whenever Filename_Override changes (if dynamically connected).
  • File_Not_Exist_FB (Digital): High (1) if the file at Filename does not exist, low (0) otherwise. Updated on module initialization and whenever Filename_Override changes (if dynamically connected).
  • File_Busy_FB (Digital): High (1) while a file operation (read, write, delete) is in progress, low (0) otherwise.
  • File_Encrypted_FB (Digital): High (1) if the file appears to be encrypted (based on header), low (0) otherwise.
  • Backup_Exists_FB (Digital): High (1) if the backup file at Filename.bak exists, low (0) otherwise. Updated on module initialization and after operations.
  • File_Size (String): The formatted size of the file (e.g., "1.23 KB" or "456 bytes" or "7.89 MB"). Updated after reads or on init/Filename_Override change.
  • Digital_Output_[1-64] (Digital): Digital values (0 or 1) loaded from the file after a successful read. Unchanged on write or error. v3.1.2: driven with explicit 0/1 assignment so values from the Simpl# library correctly assert on 4-Series. v3.1.1 may not update digitals reliably after Read even when the file and library arrays are correct—upgrade to v3.1.2 for startup digital restore.
  • Analog_Output_[1-64] (Analog): Analog values (0-65535) loaded from the file after a successful read. Unchanged on write or error.
  • Serial_Output_[1-64] (String): Serial strings loaded from the file after a successful read. Unchanged on write or error.

Usage Instructions

  • Connect Read/Write/Delete/Delete_Backup/Restore_Backup to digital triggers (e.g., buttons or logic).
  • For writes: Set input signals, select Format, specify File_Location and Filename (or Filename_Override), set Enable_Backup if desired, then pulse Write.
  • For reads: Specify File_Location and Filename (or Filename_Override), pulse Read; check Detected_Format and Feedback for results, then use output signals.
  • For deletes: Specify File_Location and Filename (or Filename_Override), pulse Delete; check Feedback and File_Exists_FB for results.
  • For backup deletes: Specify File_Location and Filename (or Filename_Override), pulse Delete_Backup; check Feedback and Backup_Exists_FB for results.
  • For restore: Specify File_Location and Filename (or Filename_Override), pulse Restore_Backup; check Feedback.
  • For encryption: Set Encrypt high and provide Encryption_Key for writes. For reads, encryption is auto-detected via header; provide the correct key if File_Encrypted_FB is high.
  • Backups are created as [FileName].[FileExtension].bak in the same directory. If Enable_Backup_History is high, old backups are archived to .bak.yyyyMMdd.gz.
  • Use Format_Override (1-6) to override the Format parameter at runtime.
  • Use Filename_Override (non-empty string) to override the Filename parameter at runtime.
  • Thread-safe via mutex; multiple instances can share files but operations are serialized.
  • Errors are reported via Feedback and Crestron console (GenerateUserError).
  • Supports up to 64 signals per type (expandable to 256); unused signals are ignored if zero/empty.
  • Ensure the paired SIMPL# library (File Reader / File Reader.dll / .clz) is deployed and referenced correctly. v3.1.1 and v3.1.2 share this library name.
  • For system startup configuration that must restore digital states, use module v3.1.2 (or later). v3.1.1 can still write/read analogs and serials correctly with the current library.
  • JSON files may be produced by this module or by external tools. Expected top-level (or nested under data / signalData) arrays: digitals, analogs, serials (property names case-insensitive). Arrays may be shorter than 64; missing slots remain 0 / empty. Digital elements may be 0/1, integers, or JSON booleans. Optional crc32 is ignored for pass/fail.

Examples

Example 1: JSON Configuration Storage (Persistent Settings)

Use Case: Store and load system configurations like volume levels, lighting scenes, or digital mode flags at processor startup.

  • Setup:
    • Format = 4 (JSON).
    • FilePath$ = \NVRAM\config.json.
    • Connect Analog_Input_1 to Volume_Level.
  • Write:
    • Set Analog_Input_1 = 50%.
    • Pulse Write.
    • Expected: JSON file created, Feedback$ = "File written in JSON format with checksum", File_Exists_FB = 1.
  • Read:
    • Pulse Read.
    • Expected: Detected_Format = 4, Analog_Output_1 = 50%, Feedback$ = "Valid JSON detected and parsed".

JSON is compact and structured; ideal for configurations. Example industry-style object (optional fields omitted; shorter arrays OK):

{
  "digitals": [0, 1, 0, 1],
  "analogs": [8, 16, 32, 64],
  "serials": ["Room A", "Scene 1", "", ""]
}

Boolean digitals are also accepted (e.g. [false, true, false, true]). When writing from this module, a full 64-element set of arrays is stored and an optional crc32 field may be included for tooling; readers do not require it.

Example 2: Encrypted CSV Logging (Secure Data Logging)

Use Case: Log temperature data securely with backup.

  • Setup:
    • Format = 2 (CSV).
    • FilePath$ = \CF0\tempLog.csv.
    • Encrypt = 1 (high).
    • Encryption_Key$ = "MySecretKey12345" (16 chars).
    • Enable_Backup = 1 (high).
    • Connect Analog_Input_[1-5] to temperature sensors.
  • Write:
    • Set inputs: Analog_Input_1 = 25000 (25°C scaled), etc.
    • Pulse Write.
    • Expected: Encrypted CSV file and .bak created, Feedback$ = "File written in CSV format with checksum and encryption", File_Encrypted_FB = 1, Backup_Exists_FB = 1.
  • Read:
    • Provide matching Encryption_Key$.
    • Pulse Read.
    • Expected: Data decrypted, integrity checked, outputs populated.
  • Restore:
    • If main file corrupted, pulse Restore_Backup.
    • Expected: File restored, Feedback$ = "Backup restored".

Use for sensitive data; test decryption to ensure key consistency.

Example 3: Binary Delete and Integrity Check (Temporary Data Cleanup)

Use Case: Write temporary binary data for a gaming setup, verify integrity on read, then delete.

  • Setup:
    • Format = 5 (Binary).
    • FilePath$ = \CF0\tempGameData.bin.
    • Connect Digital_Input_[1-10] to game states.
  • Write:
    • Set inputs and pulse Write.
    • Expected: Binary file with checksum.
  • Read:
    • Pulse Read.
    • If tampered: Detected_Format = -2, Feedback$ = "Integrity check failed for Binary".
    • If valid: Outputs match, File_Size$ shows size.
  • Delete:
    • Pulse Delete.
    • Expected: File removed, File_Exists_FB = 0, Feedback$ = "File deleted successfully".

Ideal for high-density data; binary is compact but less human-readable.

Example 4: Multi-Format Auto-Detection (Migration from Legacy Systems)

Use Case: Read from an existing XML file and write to INI for format migration.

  • Setup:
    • FilePath$ = \NVRAM\legacy.xml (existing XML file).
  • Read:
    • Pulse Read.
    • Expected: Detected_Format = 2 (XML), data loaded to outputs.
  • Write to New Format:
    • Change Format = 4 (INI).
    • Change FilePath$ = \NVRAM\newConfig.ini.
    • Pulse Write (uses loaded outputs as inputs).
    • Expected: New INI file created.

Demonstrates auto-detection for handling mixed-format archives.

Version History

  • v3.1.2 — 7/16/2026 — RGW / AI
    • SIMPL+ (v3.1.2 module only): Fixed Digital_Output_[x] not asserting after a successful Read. Values from the Simpl# ushort arrays are now applied with explicit 0/1 digital assignment (required for reliable 4-Series digital restore at startup).
    • SIMPL# library (shared by v3.1.1 and v3.1.2): JSON read accepts industry-standard objects—case-insensitive digitals / analogs / serials, optional nested data or signalData wrappers, shorter-than-64 arrays, boolean or numeric digital elements. Optional crc32 is no longer a hard integrity reject (re-serialize CRC was brittle and blocked valid external JSON).
    • Paired Simpl# source remains FileReader20260623.cs; library name stays File Reader so existing programs keep linking the same CLZ/DLL.
    • Module packaging / compile typically 4-Series only.
  • v3.1.1 — 5/1/2026 — RGW
    • SIMPL# (retroactive for all modules using the shared library): Corrected native Text format detection in Read(). Broad substring checks (e.g. looking for "A ") could false-match content inside JSON/XML/CSV serial values (for example "DSP A output"), mis-detect the format, and cause signals to sometimes not load. Detection now uses structured markers and a dedicated LooksLikeTextFormat check (requires a valid CRC32: line and proper D/A/S lines with indices).
    • SIMPL+: Removed parameter formatting from the Simpl+ code in preparation for packaging inside a Simpl module wrapper.
    • Note: With the current shared library, v3.1.1 programs gain the text-detection and industry-JSON library behavior automatically. Digital outputs after Read still require the v3.1.2 SIMPL+ module for the explicit 0/1 drive fix.
  • v3.1 (02/25/2026) : Added File_Not_Exist_FB feedback (actual, rather than derivative of File_Exists_FB).
  • v3.0 (08/04/2025) : Initial generation with JSON support.
  • Updated (08/05/2025 – 08/06/2025) : Added file existence feedback, delete functionality, busy feedback, file size and integrity checks, CSV/INI formats, backup/rollback, optional AES encryption with related feedbacks, backup history, Format_Override / Filename_Override, Delete_Backup; File_Location/Filename split with auto file extensions from Format.
