Together

UDP Broadcast and Receive v2.0 is the socket. It sends MAC,UID,Data to 255.255.255.255 and receives every other processor's line on the same port. UDP Extract Data v2.0 has no socket. It reads the beacon's outputs and latches one match.

One beacon

Hold Enable high. Put a real MAC on Mac. The timed announce waits until Mac looks like a MAC.

One Extract per peer

Add a copy for each peer this program acts on, not one per processor on the network. Wire Packet_Rx and the four Received strings across. Leave Enable_FB unwired.

Announce

While Enable is high and Announce_Interval is not 0s, the module sends the current packet on that period, including when Data is empty. The first announce goes out as soon as the socket is open and Mac looks like a MAC. Retrigger, and a non-empty change of Data, send immediately and do not wait for the period.

Every processor running this module receives every announce. Two hundred processors at 5 seconds is about 40 datagrams a second at each one, and each datagram is parsed. Use 15 or 30 seconds when hundreds of processors share the port. Leave Reply off on that network. The broadcast is how peers learn each other. A unicast answer to every announce would be one packet for every pair.

Reply

Reply answers a sender once, the first time that IP is seen, then not again until that IP has been silent for 60 seconds. At most one reply is sent every 0.5 seconds. 128 senders are remembered. A sender past that still hears the broadcast and gets no unicast. The reply is this processor's own MAC,UID,Data, sent to that IP. It is not a copy of the packet that just arrived.

SIMPL+ keeps one destination on a UDP socket. For the reply, the listen socket is pointed at the sender and then put back on 255.255.255.255. A datagram that arrives in that gap can be missed. That is why Reply stays off when many processors announce.

Receive

Own packets are dropped. A payload equal to what this module would send, or a MAC and UID that match this module, never updates the outputs and never gets a reply.

With enforcement off, a full MAC,UID,Data fills all three fields. A MAC that is not followed by a UID puts the remainder in Received_Data. Anything else is stored as Received_Data, with the sender IP when it is known. Packet_Rx still pulses.

With Enforce MAC,UID,Data, only a full packet updates the outputs. A line with no third field, a UID where the MAC should be, or plain text leaves the last good values in place and does not pulse Packet_Rx.

A carriage return or a line feed ends one datagram. A test tool that appends a CR can deliver two copies in one receive. They are parsed one at a time, and Data stops at that CR. Two processor announces have no CR and no LF, so two of those can still arrive as one buffer. The last accepted piece is the one that is published.

A MAC whose stored length is not 12 or 17 characters is published as 00:00:00:00:00:00.

MAC shape: 12 hex digits, or 17 bytes as six hex pairs separated by : or -. UID shape: 1–32 bytes, letters, digits, hyphen, or underscore.

Match and timeout

Match_IP, Match_MAC, and Match_UID each default to [SKIP], which means that field is not used. Any combination may be active. Every active field has to match. The compare is exact and case-sensitive. If every field is skipped, the symbol never sets Online_FB.

At startup the locals take the parameters, then any override whose length is greater than 0. A change on an override stores that string as it arrives. An empty override means [SKIP] from then on. It does not fall back to the parameter.

Packet_Rx evaluates the match immediately, after the beacon has finished writing the four strings. A change on a Received input still waits 0.01 s, so this Extract can also sit on the archived v1.3 beacon, which has no Packet_Rx.

A match copies the four received strings to the four peer outputs and raises Online_FB. Those outputs are written only when the value changes. A packet that does not match leaves a held peer where it is. Peer_UID is the Received_UID of the matching packet. Peer_Data is the raw Received_Data.

TimeoutWhat silence does
0sKeeps the last match and leaves Online_FB high until a newer match replaces it.
15sDefault. Online_FB drops and the four peer strings clear when no new match arrives in that time. A repeat match restarts the time.
up to 600sSame as any non-zero time. The peer clears when the quiet stretch reaches the parameter.

A non-matching packet does not restart the timeout. The clock runs from the last packet that matched.

Versions

2026-10-19. Timed announce, Packet_Rx, and an optional once-per-sender reply. v1.3 remains in the archive and sends only on Retrigger or a non-empty Data change.
