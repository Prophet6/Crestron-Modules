Start here

UDP Census v1.0 is the presence list for 4-Series processors on one subnet. Drop it on every processor. The collector broadcasts ?POLL. Each processor that is set to answer unicasts !HERE,MAC,UID,Data back. The collector stores one row per processor, including itself.

This symbol listens on UDP port 50002 unless you change the port.

UdpCensus_v1.clz has to sit in the same folder as this module. Compiling the SIMPL+ file does not rebuild that library. After a change to the C# source, build the library, copy the .clz here, then compile the SIMPL program.

Modes

Respond and Discover can stay unwired. The parameters then decide. The first time either digital changes, that digital takes over and the parameter is no longer used.

Answer only

Respond_Mode is Answer polls. Discover_Mode is Off. Hold Enable. This processor replies to a poll and does not keep a list.

Database only

Discover_Mode is Keep the database. Respond_Mode is Off. This processor polls and stores the answers. It does not answer anyone else's poll.

Both

Both modes on. This processor polls, stores the answers, and still answers a poll from someone else.

A poll

With Discover on and a Poll_Interval other than 0s, the first ?POLL goes out as soon as the socket is open. The next one follows the interval. A rising edge on Poll runs one census even when Discover is off. That pulse does not restart the interval clock.

The poll window opens when the poll goes out. Polling_FB is high for that window. Answers that arrive while it is low are ignored. When the window closes, a row that was not seen is removed.

The row key is the UID. When the UID is empty, the key is the MAC. An all-zero MAC is not used as a key. When both are empty, the key is the IP address. UID is kept to 32 bytes and Data to 128. The collector inserts itself as the first row at the start of each poll, already marked seen, so a processor that only talks to itself still has a count of 1.

Rows

Show_Index is a list position, not a fixed slot for this processor. This processor is inserted first, so it is row 1 for as long as its UID stays the same. Changing the UID stores it as a new row and can move it off position 1.

At startup, an analog value of 0 is read once as row 1. After Show_Index has moved, 0 blanks the four Processor outputs and drops Answered_FB. Count does not change. An index past Count does the same.

Count, Enable_FB, Polling_FB, Answered_FB, and the four Processor strings update only when the new value differs from the last one written.

Notices

The error log stays quiet except for three lines. Socket and send failures still use ErrorLog.Error. An answer does not move a Debugger signal. The notice is the proof that !HERE was sent.

NoticeWhen
UdpCensus: answered 192.168.1.10:50002This processor sent !HERE to that address.
UdpCensus: added room-12 192.168.1.20A row was created. An update of a row that is already stored is silent.
UdpCensus: removed room-12 192.168.1.20A row was dropped because it missed the poll window.

Limits

  • 4-Series only. The library is UdpCensus_v1.
  • 512 rows. A row past that is not stored.
  • Answers are accepted only while Polling_FB is high.
  • The listen socket binds the LAN adapter and accepts any sender. After every send it is set back to accept any address.
  • A !HERE that arrives stuck to the front of a ?POLL is still found.
  • Help requests are not part of this symbol.

Versions

v1.0, 2026-10-20. One symbol polls, answers, or both, and keeps an indexed list of the processors that answered. Later edits in the same version: the symbol rows were grouped and left in place, the row selector was named Show_Index, a discover poll is sent as soon as the socket is open, the error log notes an answer and a row only when that row is added or removed, and an output is written only when its value changes. Show_Index shares the Count row. A blank row sits above Processor_IP. UDP_Port defaults to 50002. F1 opens this file.

The full version list is in the SIMPL+ help on the symbol.
