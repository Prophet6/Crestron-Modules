Start here

IV-CAM PTZ v1.0 drives a Crestron 1 Beyond camera with raw VISCA. It is in the Camera folder. The socket is inside the module. There is no TCP/IP Client to wire.

Hold Enable

Enable high opens the socket and allows control. Low disconnects and ignores the pad, zoom, presets, and Command.

Hold to move

Pan, tilt, and zoom run while the input is high. Release sends the VISCA stop for that axis. Stop stops both axes and the zoom.

F1 is this page

Leave IV-CAM PTZ v1.0.html next to IV-CAM PTZ v1.0.usp and IvCamPtz_v1.clz.

  1. Add IV-CAM PTZ v1.0 from Camera. This build is 4-Series.
  2. Hold Enable high to connect. Drop it to disconnect.
  3. Set IP_Address to the camera. Leave the port alone. The module uses TCP 5500.
  4. Match Camera_Address to the camera OSD. Factory value is 1.
  5. In Camera Manager, leave control on TCP, server mode, port 5500, protocol VISCA.
  6. Join the pad, zoom, and presets. On connect the module asks the power state. Awake_FB or Privacy_FB follows the answer. Privacy toggles standby and wake. A pad, zoom, home, or preset press while Privacy_FB is high sends wake, and runs that command only if the button is still held when the camera is awake and one second has passed.
  7. Watch Connected_FB. It rises when the socket is up.
A live IV-CAM-P12 accepted address-1 home, 81 01 06 04 FF, and answered 90 41 FF then 90 51 FF. That is ACK, then completion. The test program has driven that camera. Power on is 81 01 04 00 02 FF. Standby is 81 01 04 00 03 FF.

What was proven

The camera listens on TCP port 5500 and speaks raw VISCA. There is no 8-byte Sony header. Address 1 answers with 90. The home packet the module sends for address 1 is the packet that camera already accepted.

Pan, tilt, zoom, stop, and presets use that same frame: address byte, command, FF. The reply parser treats 90 4y FF as accepted and 90 5y FF as finished. An error packet replaces Status.

Loading this symbol in a program and pressing Home is still the remaining check. The socket, Connected_FB, and the button logic have not been exercised on a processor.

Connection

The Simpl# library IvCamPtz_v1 opens the socket. The program does not add a TCP/IP Client.

  • Enable high connects and allows control. Low disconnects. Commands are ignored while it is low.
  • Port is 5500. It is not a parameter.
  • IP_Address is the commissioned address. 0.0.0.0 and a blank address do not open a socket.
  • IP_Address_Override is ignored until a string arrives after startup. An unwired empty serial does not count. After the first real string, that serial is the address, even if you later clear it.
  • A non-empty override that is already present at startup is used.
  • Connected_FB is high only while the socket is up.
  • A dropped link retries every 2 seconds while an address is set.
  • Status shows Waiting, Connected, Not connected, or Connection failed as the link changes. A later button press replaces that text with the command name.
Camera Manager should stay on TCP, server mode, port 5500. The OSD protocol must be VISCA. Changing that port breaks this module.

Movement

Each direction and each zoom is level-sensitive. The press sends a drive packet. The release sends stop, unless another direction in that group is still held. Two held directions combine into a diagonal. Opposite directions on one axis cancel that axis.

  • Tilt_Up, Tilt_Down, Pan_Left, Pan_Right, and the four diagonals share one pan/tilt drive.
  • Zoom_In and Zoom_Out share one zoom drive. Both high is a zoom stop.
  • Moving_FB is high while a pan or tilt drive is running.
  • Zooming_FB is high while a zoom drive is running.
  • Stop sends a pan/tilt stop and a zoom stop even if a button is still high. The camera stays stopped until that button is released and pressed again.
  • Home sends the VISCA home command. It is not preset 0.
A pan or tilt command keeps moving until a stop packet arrives. Wire the joins as press-and-hold. A pulse with no matching low will drive the head to the end of travel.

Speeds

Pan_Speed is 1 to 24. The default is 12. Tilt_Speed is 1 to 20. The default is 10. Zoom_Speed is 0 to 7. The default is 4. Zoom 0 is the slowest variable zoom, and it is legal.

Each speed uses its parameter until a value arrives on the matching override after startup. The 0 on an unwired analog does not count. After the first real value, that analog stays in charge, including 0. Pan and tilt have no speed 0, so an override of 0 is sent as 1. A value above the top of the range is clamped.

The _FB outputs show the speed that will be sent. Changing a speed while that axis is already moving sends a new drive packet at the new speed.

Presets

Preset is 0 through 255. A higher analog is sent as 255. Store_Preset writes the current shot into that number. Recall_Preset moves to it. Last_Preset follows the last number this module stored or recalled. It stays 0 until the first one, which is also preset 0, so read it together with the stored and recalled feedback.

Preset_Stored_FB and Preset_Recalled_FB show which of those two actions happened last.

On the intelligent cameras, recalling preset 80 starts tracking and preset 81 stops it. This module will recall whatever number you give it. Do not store over 80 or 81 on a tracking camera. Preset 0 is often the home shot in the OSD. The Home input is still a separate VISCA command.

Privacy

Wake sends power on and leaves standby. Privacy is a toggle. While Awake_FB is high it sends standby. While Privacy_FB is high it sends power on. Standby stops every stream from that camera. The control socket can stay open, and the camera can still accept power on.

When the socket connects, the module sends the power inquiry 81 09 04 00 FF. 90 50 02 FF raises Awake_FB. 90 50 03 FF raises Privacy_FB. One of those two is high after the reply. Both drop when the socket drops.

Pan, tilt, zoom, home, store, and recall are held back while Privacy_FB is high. The press sends power on. The module then waits until the camera reports awake and until one second has passed, whichever is later. If that button is still held, the module sends it. If it was released, the camera stays awake and no move is sent. Stop cancels a move that is waiting on wake.

These are the Crestron CAM_Power bytes. Address 1 power on is 81 01 04 00 02 FF. Standby is 81 01 04 00 03 FF.

Command

Command sends the bytes on that input as one packet, unchanged. Include the address byte and the FF terminator. An empty string does not send. The same string sent twice does not send twice. Change the serial to send again.

Address 1 home is 81 01 06 04 FF. For another address, replace 81 with 80 plus the address: address 2 is 82.

Replies

Status keeps the name of the last command. ACK and completion do not replace it. An error does.

ReplyStatus
90 4y FFAccepted. Status stays on the command name.

90 60 03 FFCommand buffer full
90 60 04 FFCanceled
90 60 05 FFNo socket
90 60 41 FFNot executable. Often standby, or a command the camera will not run in its current mode.

The 9 in 90 is address 1. Address 2 answers with A0.

Cameras

The same raw VISCA on TCP port 5500 is what Crestron documents for the IV-CAM-P12, P20, I12, and I20, and for the older 1 Beyond PTZ heads that were left on that port. OSD protocol VISCA, address 1 through 7.

Sony SRG and BRC-X IP modules are a different dialect. They wrap every packet in an 8-byte header and use port 52381. Do not point this module at that port, and do not point a Sony IP module at port 5500.

PTZOptics and the same OEM family use these command bytes on TCP port 5678. This module will not retarget that port.
