Teams Room Help v1.0

One symbol posts a room help alert to a Teams Workflow and polls a second webhook for the latest human reply. The processor never holds a Microsoft login. Highly experimental and completely untested.

Start here

Teams Room Help v1.0 is one instance per room. A help press sends the room name and the problem. Cancel and Fixed send a follow-up. While the request is open, the symbol asks a second webhook for the newest answer and puts the sender, the time, and the text on serial outputs.

You fill in

Room name, both webhook URLs, and the shared secret. The defaults are examples. Replace them before the room goes live.

IT fills in

The group chat, the flows, and the two URLs. That setup is Teams Room Help - IT setup.docx in this folder. The last page of that handout is the sheet they send back.

The panel draws

This symbol does not draw a page. Join the presses and the serials in the touchpanel project. A picture in the IT handout is only an example of one possible page.

  1. Keep TeamsRoomHelp_v1.clz and Teams Room Help v1.0.html in the same folder as Teams Room Help v1.0.usp.
  2. Drop one symbol for the room. Paste the alert URL, the reply URL, and the secret from IT. Set Room_Name to the exact spelling in their SharePoint list.
  3. Join the issue presses you show on the page, up to eight, plus Cancel, Fixed, and Issue_Text.
  4. Show Status, and show Response_Sender with Response_Time on one line above Response_Text.
  5. Drive Holiday from the room calendar when business hours are on. Leave it low when today is a normal weekday.
Press F1 on Teams Room Help v1.0 in SIMPL Windows to open this page. Leave the HTML file next to the .usp. The comment inside the .usp is the version history.

Overrides

Every setting can be driven from the program. The parameter is the value until the matching input takes over.

InputRule
Serial overridesAn empty string uses the parameter. A non-empty string replaces it. Clearing the string returns to the parameter.
Poll_Interval_OverrideWhole seconds. 0 uses Poll_Interval. Any other value is clamped to 5–300 seconds.
Clear_After_OverrideWhole hours. 0 uses Clear_After_Hours. Any other value is clamped to 1–168 hours.
Auto_Clear_Override and Business_Hours_OverrideLeave the digital unwired to use the parameter. After the digital changes, that digital stays in charge. A digital already high at startup is in charge. A wired low that never changes still uses the parameter.

Polling

A successful help clears the three reply serials, stores the send time, raises Request_Active_FB, and arms the timer. The first poll is one interval after that success. Each later poll waits Poll_Interval.

The poll is POST with the room name. HTTP 200 and {}, or a body with no text field, leaves the reply serials as they are. A non-empty text field updates sender, time, and text.

Each call waits 8 seconds, then retries once. The body is not written to the error log. The webhook URL is not written either, because a Teams webhook URL contains sig=.

The timer keeps running after the visitor leaves the page. It stops when Cancel succeeds, Fixed succeeds, or auto-clear fires. Outside the business window the timer still wakes up, so it can notice the window opening and can notice the deadline. It does not place an HTTP call while the gate is closed.

Hours and holidays

Time is the processor's local time. Set the processor clock and time zone. Monday through Friday are business days. Business_End itself is closed: 17:00 is not an open minute.

Business_Hours_Only defaults to Off so a request after 17:00 still hears the reply. While it is off, Holiday does nothing. Clear_After_Hours is clock time from the successful help. Nine hours from Tuesday 10:00 is Tuesday 19:00. Nine hours from Friday 16:00 is Saturday 01:00.

While Business_Hours_Only is on, polls go out only from Business_Start inclusive to Business_End exclusive, on weekdays that are not the holiday. Hours outside that window, weekends, and the holiday day do not count toward Clear_After_Hours. The request stays active. Status stays Request sent. Turning the gate on does not clear the request.

Holiday means the whole current local day. Future holidays are not known, so Clear_At assumes later weekdays are normal until the input says otherwise. Raising Holiday today removes today from the count, including time already accumulated today, and moves Clear_At.

With the default window 08:00–17:00 and 9 hours, business-hours mode clears at these times.

Auto_Clear off keeps the request up until Cancel or Fixed. The business-hours gate can still suppress polls. Clear_At is empty. Auto-clear does not post another Teams message. Status becomes Request expired and the last reply stays until the next successful help.

08:00 to 17:00 is 9 hours. The default of 9 matches one business day when the gate is on. Use 24 on the hours parameter, with the gate off, for a full clock day.

JSON

Both calls are POST with Content-Type: application/json and the secret header. Field names and action words are parameters, so a flow that already chose different names can be matched without a new compile.

A help post, with the defaults and room Conference Room, is:

{
  "room": "Conference Room",
  "action": "help",
  "issue": "Audio problem",
  "message": "Urgent - Conference Room: Audio problem"
}

action is help, cancel, or fixed unless those parameters were changed. message is the template after {room} and {issue} are replaced. The flow can post that field into the chat and skip building the sentence itself.

Cancel and fixed use the same keys. Their issue value is empty. Their message value comes from Template_Cancel or Template_Fixed.

The reply request is one field:

{ "room": "Conference Room" }

A waiting answer is:

{
  "sender": "Alex",
  "text": "Conference Room - on our way",
  "at": "2026-10-20T15:04:00Z"
}

at is ISO-8601. A value with a Z or an offset is read as that instant. A value with no zone is read as UTC. It is then shown in processor local time. Nothing waiting is HTTP 200 and {}.

Quotes, backslashes, and line breaks in a value are escaped. The reply parser reads the configured field names. A value that is not a string, such as null, is treated as empty.

Replies

The symbol shows a reply only when the text field is non-empty. If at parses to more than two minutes before this help was sent, the whole reply is ignored. That keeps yesterday's stored answer off the panel when the alert flow forgot to clear it. A reply with no at is shown, because it cannot be filtered by time.

Cancel and Fixed do not wipe the reply serials. The next successful help does.

Two rooms need two symbol instances. Each poll sends that instance's room name. The flows must store one answer per room name. Spelling has to match Room_Name, including capitals.

A thread reply under the alert often never reaches the save flow. Staff send a new message in the chat, and that message has to contain the room name. The bot's own alert must not be saved as the answer. Both of those rules live in the flows, not in this symbol.

HTTPS

Host verification and peer verification are on unless Allow_Insecure_TLS is high. Leave that digital low for logic.azure.com. Redirects are followed. The client does not keep the connection open.

A code from 200 through 299 is success, including 202. Any other code, a timeout, or a throw is Could not reach support after the retry. The secret is sent as the raw header value. It is not logged.

Limits

  • 4-Series only. There is no 3-Series build.
  • Eight preset issue presses. The example picture shows four.
  • One active request per symbol. A new successful help replaces it.
  • Poll interval 5 to 300 seconds. Clear time 1 to 168 hours.
  • The symbol will not create an Xyte ticket, call Microsoft Graph, delete a Teams message, or host the webhook.
  • Real Teams Urgent (importance: urgent) is a step inside the flow, if IT adds it later. This symbol's urgent signal is the word Urgent in Template_Help plus whatever @mention the flow adds.
  • //#CATEGORY "0" stays commented until the symbol is inside a user module. The file name is the symbol name.
